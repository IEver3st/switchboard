What still prevents a “fully functional” claim

These are external environment or physical-hardware gates. They should not be replaced with mocks or inferred from deterministic tests.

Driver and Windows matrix

  • Install the Windows 11 24H2 WDK Visual Studio component.
  • Build the pinned transport-only driver and confirm production identities.
  • Complete HLK audio tests and Windows-accepted production signing.
  • Install, upgrade, and uninstall cleanly; verify all eight 48 kHz stereo PCM endpoints.
  • Verify per-application assignment across process restart and session recreation.

Physical audio and lifecycle

  • Listen to Personal, Stream, Clip, and processed virtual microphone paths on real applications.
  • Inspect saved replay files for intended Clip mix, microphone track, sync, and metadata.
  • Measure latency, glitches, overrun/underrun behavior, channel mapping, and clipping.
  • Exercise endpoint changes, disconnect/reconnect, killed-host recovery, and close-to-tray.
  • Run 500 start/stop cycles and a 24-hour active graph soak with flat handles and memory.
Next action: install the WDK component, build and test-sign the driver in an isolated development environment, install the eight endpoints, then execute the driver/physical qualification matrix above. Only after those checks pass should Switchboard advertise end-to-end audio routing as fully functional.
